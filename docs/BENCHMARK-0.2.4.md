# TwoSeat 0.2.4：Voxy 32 → 64 → 128 区块实测

2026-11-12，在本机独立世界依次完成32、64、128区块；每档完成后查看原生游戏截图才进入下一档。两名真实玩家、两套960×1080视口，近景8区块、模拟8区块保持不变。

## 环境与方法

Minecraft1.20.1、Forge47.3.33、Java17.0.21；TwoSeat0.2.4-alpha + Embeddium0.3.31 + [指定Neo Voxy本地构建](VOXY.md)。CPU Ryzen7 9700X，GPU RTX5070；1920×1080、精细画质、全部粒子、无光影、VSync关闭、不限帧（原版maxFps=260表示无限），Java最大堆8GiB。Voxy后台4线程、subdivision=256、sky fog=256。

世界seed12345，晴天正午，P1(-127.5,160,0.5)朝东/yaw-90、P2(128.5,160,0.5)朝南/yaw0，俯角均25度。每档先生成、保存并导入地形，等待导入和网格队列清空，再预热20秒，连续取2次各15秒。所有采样全程前台，未同时执行构建或地形生成。测量整窗完成两侧渲染的帧间隔。

## 实际结果

FPS列为两样本总帧数/总时长；其余列保留两次读数，避免把分位数或堆快照当作可直接合并的统计量。

| LOD区块 | 整窗平均FPS | 1%low FPS，两次 | 采样末Java堆已用GiB，两次 | 平均服务端tick毫秒，两次 |
|---:|---:|---:|---:|---:|
| 32 | 487.4 | 238.0 / 250.2 | 1.46 / 1.99 | 1.17 / 1.19 |
| 64 | 451.6 | 240.4 / 237.6 | 1.85 / 1.48 | 1.00 / 1.03 |
| 128 | 419.8 | 234.0 / 229.7 | 1.64 / 2.11 | 1.04 / 0.98 |

32→128下，本场景平均FPS约下降13.9%。128档两次p99帧时间3.883 / 3.8811ms； 六样本P2天气时钟回退均为0，两侧renderer时钟均持续前进。此次场景没有用于生物动画测量的近处实体，不能据此声称重复完成了0.2.2的牛/熔炉模拟测试。

堆已用是采样结束时的瞬时值，受GC及同一JVM按顺序累积缓存影响，不是进程总RAM或长期最低需求。Voxy调试行的Buf/Tex容量包含稀疏/虚拟分配，不能当作物理显存占用。当前两套GPU几何/模型图集尚未去重。

## 生成与导入

32档覆盖半径640格，49秒；64档扩大到1152格，2分钟；128档扩大到2176格，6分12秒。后档沿用前档已生成区域，因此不是三个从空白世界开始的独立耗时。Chunky报告的6561/21025/74529是任务遍历位置数，不等同于圆形区域全部实际新生成的区块数。第一轮分档导入约2–3/8/25秒。修复模型并发后恢复同一观察存档，在最终代码上重新依次32→64→128采样；此时三档都复用完整128缓存，分别只绘制设定范围，每次全量导入约24–25秒。原始完成状态见[准备记录](evidence/0.2.4/preparation.json)。生成/导入期间的卡顿没有混入稳定观景FPS；进入新世界仍要等待数据积累。

## 视觉与兼容回归

- 三档均检查真实Minecraft PNG：两侧远山/地形存在，32→64→128范围增加。状态探针同时核实两个独立viewport/renderer、同一WorldEngine、两份dirty/biome监听、非零LOD网格及空后台队列。
- 实际把两人各320格外（超出8区块近景）的塔换色，再恢复：两边画面均正确改变。P2退出后P1单视角仍收到更新，P2重新加入后两侧再次更新。不是仅检查设置数值。
- 测帧完成后另放两座高空黄色塔，距P1/P2中心约1931/1803格，均超过64区块的1024格。64档黄色像素两侧均0，128档分别192/235；两张原生截图均已人工查看。它们未加入上表的固定场景，避免改变采样负载。对照：[64](screenshots/0.2.4-reach-64.png)、[128](screenshots/0.2.4-reach-128.png)。
- 修复前红测出现P1远景缺失，虽然读到约557FPS，已判为无效，不计入本表。根因与修复见[兼容说明](VOXY.md)。
- 操作回归抓到MipGen静态临时数组/队列被两个模型线程共用的越界，增加ThreadLocal互操作补丁后，两线程各1000次、8种透明纹理的真实处理输出逐字节匹配串行参考。随后首次连接、原17输入和9菜单用例全部通过；未安装Voxy的纯Forge组合也通过双玩家及9菜单回归。菜单夹具扩大观察平台，避免第二段移动走出平台后自由落体干扰“菜单所属玩家不动”的判断。
- 最终clean JAR的48个TwoSeat类与本表测帧包逐字节一致，内置Controlify/YACL归档内每个文件的内容也一致；只更新许可资源、清单和归档时间戳。自动状态源经过真实Controlify绑定链，不能替代用户实体手柄验收。

本表是固定相机、短时观景性能，不是密集生物/红石、快速飞行、跨维度或长期稳定性保障。128是LOD远景范围，世界完整模拟仍为每位玩家附近8区块。
