# TwoSeat 单进程双人分屏

**TwoSeat 0.2.4-alpha**，适用 **Minecraft Java 1.20.1 / Forge 47.3.33 / Java 17**。一个 Minecraft JVM、唯一集成服务器、两名真实玩家，左右各有视角、HUD 和物品栏。本版内置 **Controlify: Forgified 2.1.9** 及配置库：玩家一键鼠、玩家二优先使用手柄，保留原键盘分屏。

## 可选 Voxy 远景实验

0.2.4新增双视角Voxy兼容，按用户要求顺序测试 **32 → 64 → 128区块LOD**，近景和模拟保持 **8 / 8区块**。Voxy地形数据库与世界数据共用，两个摄像机使用各自的渲染器、裁剪状态和半屏输出。修复了后一视角覆盖共享数据库更新回调、导致前一视角远景不更新的问题；离开一名玩家后保留另一方监听。另隔离了两套模型烘焙线程共用的静态临时工作区，修复透明纹理处理时的队列越界。

基础分屏仍只需TwoSeat一个JAR，Controlify/YACL继续内置。远景实验另需 **Embeddium 0.3.31** 与本次验证的 **Neo Voxy 1.20.1/Java17本地构建**；不用Connector或光影。Voxy许可禁止再分发，其实现和二进制均未并入TwoSeat或公开源码包。指定上游、兼容范围和本地构建说明见[Voxy实验说明](docs/VOXY.md)，分档数据及截图见[0.2.4测试报告](docs/BENCHMARK-0.2.4.md)。

LOD显示已有的地形数据；未生成、未探索、未导入的区域会缺失，单纯把距离设成128不会自动生成远处地形。测试实例先准备地形、保存、导入，然后才测缓存建好后的帧率。Chunky仅用于本次独立测试世界的地形准备。

## 本版手柄操作

只安装一个 TwoSeat JAR，不要另装 Controlify / YACL。连接手柄、F8 加入即可开始；0.2.1 移除了设备信息提交页和自动弹出的设置向导，标准手柄直接使用上游默认绑定与死区。绑定、手动校准、映射和灵敏度可在“选项→控制”的 Controlify 入口调整。若一个设备同时暴露标准手柄和无映射的原始接口，会自动选择可用的标准接口；只有原始接口的设备需先手动完成映射。

玩家二默认左摇杆移动、右摇杆转向、A 跳跃、按下右摇杆潜行、RT 攻击/持续挖掘、LT 使用/放置、LB/RB 快捷栏、Y 背包；背包中左摇杆移动光标、方向键吸附槽位、A 取放、X 拿一半、Y 快速移动、B 返回。

F9 切换“P2仅键盘 / 有手柄时用手柄”。手柄使用独立鼠标对象和虚拟光标，允许双方同时打开各自背包，P2开背包时P1仍可移动。无活动手柄时退回下方键盘布局；手柄模式不叠加玩家二字母键移动。Forge 列表保留内置模块的名称和作者。详见 [手柄集成与验收](docs/CONTROLIFY.md) 及 [LGPL声明和源码](THIRD-PARTY.md)。

## 安装与开始

1. 新建纯净的 Minecraft 1.20.1、Forge 47.3.33 测试实例，使用 Java 17。
2. 移除旧版 TwoSeat，将 `twoseat-1.20.1-forge-0.2.4-alpha.jar` 放入该实例的 `mods` 文件夹。
3. 启动游戏，进入一个单人世界，等待地形加载完成。将输入法切到英文，点击游戏窗口。
4. 按 **F8** 加入第二玩家，显示左右分屏。再次 F8 让第二玩家离开。
5. 正常使用原版“保存并退出”。再次进入相同世界，按 F8，第二玩家会恢复自己的数据。

## 基本操作

| 操作 | 玩家一（左侧） | 玩家二（右侧） |
| --- | --- | --- |
| 移动 | WASD | I / J / K / L |
| 转向 | 鼠标 | 方向键 |
| 跳跃 | 空格 | 右 Ctrl |
| 潜行 | 左 Shift | 右 Shift |
| 攻击 / 挖掘 | 鼠标左键 | U（挖掘需按住） |
| 使用 / 放置 | 鼠标右键 | P |
| 选择快捷栏 | 数字键 / 滚轮 | 小键盘 1–9（开启 Num Lock） |
| 自己的背包 | E | O |

以上键盘模式共享一个物理鼠标光标；P1游戏中保持自己的鼠标瞄准，P2键盘界面可用方向键、Tab、Enter及F10，操作鼠标界面时先让P1释放光标。手柄模式使用独立虚拟光标。O关闭P2背包，Esc始终属于P1。玩家二固定名为`TwoSeatGuest`，使用稳定UUID，数据由原版存档保存。

## 独立游戏菜单

分屏时，**Esc打开/关闭P1菜单**，**手柄菜单键（Start）或F10打开P2菜单**，手柄B返回。每侧有自己的返回游戏、成就、统计和设置界面；一侧开菜单时，另一侧仍可移动、转向和操作，世界也继续更新。两侧可以同时打开菜单，各自返回。

设置按钮注明“影响双方”，因为显示与资源设置属于同一个游戏窗口。P2的“离开分屏”只让P2保存离开；P1的“保存并结束双方游戏”会正常保存并结束这次世界会话。只剩一名玩家时，重新打开Esc菜单恢复原版单人暂停行为。详见[菜单验证](docs/MENUS.md)。

## 个人存档与进度

同一个世界中的地形、方块和世界时间按原版联机规则共用。每名玩家以自己的 UUID 保存个人背包、装备、末影箱、经验、位置、重生点、配方、成就进度和统计：分别位于世界目录的 `playerdata/<UUID>.dat`、`advancements/<UUID>.json`、`stats/<UUID>.json`。正常保存退出后，重新进入原世界再按 F8 载入 P2 的个人数据。

0.2.0 的成就／配方提示队列被两屏共用，导致一个人解锁后两边都弹提示；0.2.1 已给两名玩家各自的提示队列。原版聊天中的“某玩家达成进度”公告仍会发给双方；公告中有玩家名字，各自的进度记录分别计算。

## 天气、粒子与8区块模拟

0.2.2补齐P2的LevelRenderer.tick、环境动画和粒子更新，修复右屏雨线每刻反复跳动的问题；两名玩家各自保存活动粒子/发射器/待加入队列/组计数，粒子提供器和纹理图集继续共用。该修复没有降低P2生物/方块的模拟频率；0.2.4的可选LOD只处理远景。

本机纯净试玩实例已设为加载距离8、模拟距离8。其他实例也请在视频设置中将两项分别设为8；模组不会强制覆盖玩家自行选择的距离。集成服务器按原版玩家区块票据维持每名玩家周围的模拟，重叠区域只在同一服务器中模拟一份。验证和帧率数据见[天气、模拟与帧率测试](docs/BENCHMARK-0.2.2.md)。

- 真实 F8 / O / Esc 按键，原版菜单“保存并退出→重进→F8”，以及独立身份、位置和背包恢复。

详见 [验证记录](docs/VERIFICATION.md)。已在 Forge 开发客户端，以及官方安装器生成的正式 Forge 运行时验证；后者从 `mods` 目录加载最终重混淆 JAR，独立启动、双人分屏、移动 / 转向与保存退出均通过。

## 当前限制

这是可测试Alpha，当前只分配一支活动手柄给玩家二。已加入指定版本的Voxy实验兼容，尚未加入物理双键鼠、光影、整合包兼容或近景网格去重；跨维度、死亡重生、复杂容器、全部鼠标拖拽、手柄多设备切换、震动和长期稳定性未完整验收。粒子纹理/生成器仍共用，活动粒子、待加入队列和计数按玩家分开；音频继续以P1为监听中心。为适配Forge47.3.33，禁用一个上游有映射诊断的可选配方书光标吸附Mixin；普通背包槽位吸附与物品操作保留。

本版正式Forge客户端自动回归经过真实Controlify绑定/死区/虚拟鼠标管线，验证移动、转向、输入隔离、放置、挖掘、PvP、背包取放、双背包和断开后键盘回退。测试设备只替代硬件状态来源，不等于真人按手柄全流程验收。SDL3曾实际识别本机飞智APEX5/XInput设备，真人游玩仍待试玩。

测试中出现过一次 `glfwSwapBuffers → d3d11.dll` 的原生访问异常（`tools/run-04.log`、`mod/run/hs_err_pid5508.log`）；原因未确定。后续约四分钟的复测及正常保存重进未复现，不能据此宣称已根治。请先用测试存档验收。

## 源码与构建

- 源码：`mod/src/main/java/local/twoseat/`。
- 构建：Java 17，执行 `cd mod` 后 `gradlew.bat clean build`，产物在 `mod/build/libs/`。
- 本机可直接执行 `build.ps1`，复用已经准备的 JDK / Gradle / 项目专用缓存。
- 开发启动：`run-dev.ps1`；Gradle `-Pprobe runClient` 才启用测试驱动，普通安装默认关闭。
- TwoSeat原有独立代码采用MIT；Controlify及适配代码、YACL使用LGPL-3.0-or-later。完整声明、对应源码及内置模块替换方法见THIRD-PARTY.md。Forge MDK与Gradle wrapper保留各自许可。

两份长期方案原件保存在 `docs/requirements/`，当前范围与上游核验见 [第一阶段记录](docs/PHASE1.md)。本阶段每个玩家有自己的客户端世界视图与区块缓存；资源管理器、纹理、模型等共用，服务器世界只模拟一份。客户端缓存与网格共享优化留到后续阶段。
